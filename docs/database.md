# Database (Postgres + Valkey)

## Postgres
- Image `postgres:16`; creds from `.env` (`POSTGRES_USER/PASSWORD/DB`). Bound to `127.0.0.1:5432`.
- Healthcheck (`pg_isready`) gates dependents via `depends_on: condition: service_healthy`.
- **`db/init/`** runs **once on first init** (`docker-entrypoint-initdb.d`) — bootstrap ONLY
  (extensions, extra roles/DBs). The repo ships `01-extensions.sql` (pgcrypto, uuid-ossp).
  **Do not put migrations here** — they'd only run on a fresh volume.

## Schema & migrations — the ORM owns it
The app creates/updates its schema via its ORM, applied on startup. No Flyway/standalone migration
tool. Per language:
- Python → SQLAlchemy (stub uses `create_all`; Alembic for real migrations).
- Node → Prisma (`prisma migrate deploy`); stub uses `CREATE TABLE IF NOT EXISTS`.
- Go → in-code migration / `CREATE TABLE IF NOT EXISTS`.
`make migrate` is an optional hook to run your ORM's migrate command explicitly.

## Valkey
- Image `valkey:7` (Redis-compatible), `--requirepass ${VALKEY_PASSWORD}`. Bound to `127.0.0.1:6379`.
- Connect from an app with the standard redis client: host `valkey`, port 6379, password from env.
- Healthcheck is an authenticated `PING`.

## pgAdmin (profile: tools)
Pre-connected to `db` via `servers.json` + a `pgpass` (generated by `make init`, mode 600) referenced
through `PassFile` — so it connects without a manual password prompt. `PGADMIN_REPLACE_SERVERS_ON_STARTUP`
reloads the server definition each start. http://localhost:8080.
